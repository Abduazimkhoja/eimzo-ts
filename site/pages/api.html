Cancellation

Every method except unloadKey accepts { signal } (an AbortSignal), like fetch. An aborted call rejects with signal.reason (an AbortError by default), not with EimzoError.

const controller = new AbortController();
const keys = await eimzo.listKeys({ signal: controller.signal });
await eimzo.sign(data, { signal: AbortSignal.timeout(60_000) });

A call that is still queued, or still waiting for init(), never reaches E-IMZO. A password window that E-IMZO has already opened stays open; the next queued operation waits for it, so a second window never appears. A key loaded by an aborted loadKey() or login() is unloaded again.

Errors

Every error is an EimzoError: code, params, localized message, E-IMZO's reason and status, WebSocket wsCode, backend httpStatus. Check with isEimzoError(e, 'CODE').

Codes: NOT_INSTALLED, WEBSOCKET_UNSUPPORTED, TIMEOUT, OUTDATED_VERSION, API_KEY_REJECTED, WRONG_PASSWORD, CANCELLED, KEY_NOT_FOUND, FILE_TOO_LARGE, KEY_NOT_LOADED, BACKEND_NOT_CONFIGURED, BACKEND_ERROR, EIMZO_ERROR. What each one means: troubleshooting.
