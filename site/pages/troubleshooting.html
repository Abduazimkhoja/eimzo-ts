Troubleshooting E-IMZO errors

Check error.code first, then error.reason and error.status (raw data from E-IMZO) or error.httpStatus (your backend).

CodeCauseFix
NOT_INSTALLEDE-IMZO is not running or not installed; the WebSocket to 127.0.0.1 closed.Start E-IMZO or install it from e-imzo.uz.
API_KEY_REJECTEDNo valid API key for the page's domain.DEV_API_KEYS on localhost; Developer mode in the E-IMZO tray for test domains; an issued key for each production domain.
OUTDATED_VERSIONE-IMZO is older than minVersion (4.86 by default).Update E-IMZO.
WRONG_PASSWORDWrong password. reason "Password is not ASCII" means a non-Latin keyboard layout.Let the user retry. E-IMZO has already shown its own message.
CANCELLEDThe user pressed Cancel in the password window.Reset the UI; do not show an error.
KEY_NOT_FOUNDE-IMZO forgot the key: restart, 24 hours, or the key was unloaded.With autoReloadKey (default) sign() retries once. Otherwise call loadKey().
KEY_NOT_LOADEDsign() before loadKey().Fix the calling code.
FILE_TOO_LARGEFile is larger than maxSize (10 MB by default).Raise maxSize or reject the file.
BACKEND_NOT_CONFIGUREDlogin() without getChallenge/login, or signDocument() without timestamp.Configure backend.
BACKEND_ERRORYour backend returned non-2xx or status other than 1.Check httpStatus and params.detail.
TIMEOUTtimeoutMs is set and there was no answer in time.Raise or remove timeoutMs.
WEBSOCKET_UNSUPPORTEDNo WebSocket, e.g. the code ran on the server during SSR.Call it only in the browser.
EIMZO_ERRORAny other E-IMZO error.Read reason.

Other symptoms

  • The password is asked on every signature. Several clients, or loadKey() before every sign(). Keep one client and load the key once.
  • Fewer keys than E-IMZO shows. Keys without TIN and PINFL are skipped by design.
  • Works on localhost but not on the real domain. No API key for that domain.
